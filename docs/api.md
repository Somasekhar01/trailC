# REST API plan

All successful responses use `{ "data": ... }`; errors use `{ "error": { "code", "message", "fields?" } }`. JSON request bodies are limited to 1 MiB. The API prefix is `/api/v1`.

## Health and auth

| Method | Path | Access | Purpose |
|---|---|---|---|
| GET | `/health` | public | Process health |
| GET | `/ready` | public | MongoDB readiness |
| POST | `/auth/register` | public | Create a customer account; password is hashed |
| POST | `/auth/login` | public | Issue short-lived bearer JWT |
| GET | `/auth/me` | customer/staff | Return current account |

## Menu, checkout, reservations, community

| Method | Path | Access | Purpose |
|---|---|---|---|
| GET | `/menu?category=&search=&featured=` | public | Available menu items; search uses Mongo text index |
| GET | `/menu/categories` | public | Available categories |
| POST | `/orders` | public | Create pickup/delivery request; requires unique `Idempotency-Key`; server prices items and reserves stock |
| GET | `/orders/:id?token=<tracking-token>` | order bearer token | Return limited tracking status; token is generated by the customer browser and only its hash is stored |
| POST | `/orders/:id/checkout` | `x-order-tracking-token` | Create Stripe Checkout session only when configured |
| POST | `/payments/stripe/webhook` | Stripe signature | Verify event; only webhook can mark paid |
| POST | `/reservations` | public | Request a capacity-limited date/time reservation |
| POST | `/community` | public | Submit feedback/review/media link with consent; starts pending |
| GET | `/community` | public | Show approved featured submissions only |

## Staff endpoints

Send `Authorization: Bearer <JWT>`; roles are checked against the persisted account.

| Method | Path | Roles | Purpose |
|---|---|---|---|
| GET | `/staff/orders?status=` | owner, manager, cashier, kitchen | List newest orders |
| PATCH | `/staff/orders/:id/status` | owner, manager, cashier, kitchen | Move an order through the queue |
| GET | `/staff/reservations` | owner, manager, cashier | View active requests |
| PATCH | `/staff/reservations/:id` | owner, manager, cashier | Confirm/cancel request |
| GET | `/staff/community` | owner, manager, moderator | Review pending submissions |
| PATCH | `/staff/community/:id` | owner, manager, moderator | Approve, reject, feature, or remove |

## Next API slices

Catalog CRUD/inventory audit, promo validation, customer support, merchandise variants/shipping/returns, reporting, refund provider integration, audit events, authenticated order tracking, and staff user provisioning should be added before production launch.
